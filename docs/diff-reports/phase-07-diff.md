## 5. 記録すべき知見（`document-knowledge` 連携）

意思決定ログへ残す内容:

1. **Godot で `.tres` を上書き生成するときは `Resource.take_over_path()`。**
   `ResourceSaver.FLAG_CHANGE_PATH` だけだと、既存ファイルがリソースキャッシュに載っている
   2 回目以降で「同じパスを持つリソースが 2 つある」となって保存が弾かれる。
   集約リソースを ExtResource 参照にしたいなら、**参照される側を先に保存して `resource_path` を付ける**。

2. **`SceneTree._initialize()` の中で `add_child()` した Node は、その場ではツリーに入っていない。**
   phase-03 の R-08（`onready` の解決）と同じ根で、今回は `HTTPRequest.request()` が
   `ERR_UNCONFIGURED` を返す形で出た。**しかもホスト自身がツリー外だと `get_tree()` も null を返す**ので、
   `Engine.get_main_loop() as SceneTree` から取る必要がある。**ヘッドレス CLI を書くたびに踏む罠。**

3. **`PackedStringArray` などの値型は、プロパティ越しに `append` しても書き戻らない。**
   `obj.packed_array.append(x)` はコピーを変更して捨てる。
   **公開するなら追加用のメソッドをクラス側に持たせる。**

4. **正常系の入力でエンジンのエラーログを吐く API を、検証コードの中で使わない。**
   `JSON.parse_string` は失敗時にログを吐くので、「壊れた JSON を渡す」テストがログを汚す。
   `JSON.new().parse()` なら戻り値で判定でき、エラー行も取れる。

5. **警告の重複排除は「入力」ではなく「出力（解決結果）」で畳む。**
   フォールバックを持つ解決関数では、別々の入力が同じ結果になる。
   入力側で畳むと同じ警告が複数出る。**テストを書いていなければ気づかなかった。**

6. **GAS スクリプトは、API をモックして Node で実行すれば検証できる。**
   `SpreadsheetApp` / `Utilities` / `ContentService` の 3 つを差し替えるだけで、
   シート → JSON の変換を CI に載せられる。出力をそのまま CLI へ食わせれば経路全体が通る。

7. **`content_hash` は `generated_at` を含めずに計算する。**
   毎回変わるフィールドを混ぜると差分スキップが永久に効かない。

8. **秘密は「表示するときに伏せる」のではなく「持たせない」。**
   結果オブジェクトが CLI のログ・Dock・issue の 1 行表現と複数の経路で表に出るなら、
   どれか 1 つで伏せても他から漏れる。**入口で落とす**のが唯一まともに効く。
   実際、「取得元は伏せます」と表示した直後の行が URL を丸ごと出していた。

9. **純粋関数だけを見るテストは、その関数が呼ばれていないことを検出しない。**
   `redact_url()` の単体テストは全通過のまま、`import_from_url()` がそれを通していない
   実装を見逃した。ミューテーション（呼び出しを外す）を当てて初めて気づいた。
   **境界を守る仕組みは、境界そのものを通すテストで確かめる。**

### 6.1 U-09 は「確定した案」と違う形で実装されている

台帳の決定ログは 2026-09-03 に **U-09 を B 案（`AdvPortrait` を合成プロパティにする）で確定**
としているが、**実装は B 案ではない**。

| | 確定した B 案 | 実際の実装（phase-04） |
|---|---|---|
| ダークの書き先 | `tint: Color`（中間プロパティ） | **`modulate` の RGB のみ**（`AdvPortrait.set_modulate_rgb()` が alpha を保つ） |
| フェードの書き先 | `fade_alpha: float` | `modulate.a`（phase-03 のまま） |
| ホップの書き先 | `hop_offset: Vector2` | **`position` を直接**（phase-03 の `move_portrait` と同じ） |
| スロットの書き先 | `slot_position: Vector2` | `position` を直接 |
| 排他ターゲット | `portrait_tint:` / `portrait_alpha:` / `portrait_position:` / `portrait_hop:` の 4 つ | **`portrait_modulate:` を新設**し、`portrait_alpha:` / `portrait_position:` と合わせて 3 つ |

**実装の方が筋が悪いとは限らない。** `modulate` を「RGB＝ダーク」「A＝フェード」で
成分ごとに書き分ける手は、合成プロパティ 4 本を足すより小さい。
一方で **ホップと `move_portrait` が `portrait_position:` を取り合う**ので、
移動中に話者が変わると「後から始まった方が勝つ」で移動が打ち切られる
（台帳の決定としては許容範囲だが、B 案が消したかった副作用そのもの）。

**決着（2026-09-03）**: **実装に合わせて仕様書を書き換える**（ユーザー判断）。
仕様書 §8 に「`modulate` を成分で分ける」設計として書き直し、§13 の U-09 を確定済みへ移した。
合成プロパティ案は「取り合いが実害になったら再検討する」として注記に残す。
